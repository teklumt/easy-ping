# Next.js + Drizzle

A Next.js App Router app with Postgres through Drizzle: a bell in the header, route handlers
that send, and delivery that runs after the response.

```bash
docker compose up -d postgres     # from the repo root, or set DATABASE_URL in .env
cp .env.example .env              # fill in NOTIFY_SECRET and NOTIFY_CRON_SECRET
pnpm install
pnpm db:push                      # creates your user table, easy-ping's, and the push plugin's
pnpm db:seed                      # adds you, dana and sam
pnpm dev                          # http://localhost:3004
```

Every send reaches three channels, each with its own card on the page:

- **In-app:** the bell in the header, through `useNotifications`.
- **Web push:** press **Enable push**, allow the prompt, send yourself a reply, then look outside
  the tab. The first subscription can take a few seconds.
- **Email:** with `RESEND_API_KEY` set it really sends. Without it, an outbox provider
  (`src/outbox.ts`) keeps each rendered email for the page to show instead.

Send a reply to someone else, switch the "Signed in as" menu to them, and it is waiting.

## Files

| | |
| --- | --- |
| `src/db/schema.ts` | your `user` table alongside easy-ping's, so `drizzle-kit` manages both |
| `src/db/easy-ping-plugins.ts` | the push plugin's table, generated by `renderDrizzleSchema` |
| `src/notify.ts` | the whole configuration |
| `src/session.ts` | stand-in for your auth library |
| `src/app/api/notifications/[[...notify]]/route.ts` | mounts every endpoint in one line |
| `src/app/api/comments/route.ts` | a realistic send site |
| `src/components/Demo.tsx` | one client shared by the bell and the channel cards |

## Worth noting

**The route is an optional catch-all**, `[[...notify]]`. With single brackets the bare
`/api/notifications` feed path is a 404.

**`waitUntil` is passed explicitly.** `delivery: { mode: "deferred", waitUntil: after }`. The
library does not sniff for `next/server`, because importing a package that may not exist breaks
other bundlers. Deferred mode also needs `POST /api/notifications/cron` on a schedule in
production, as the durability floor.

**Plugin tables live in a generated file.** `createSchema()` covers the core tables only. After
upgrading easy-ping, regenerate `src/db/easy-ping-plugins.ts` with `renderDrizzleSchema` and run
`pnpm db:push`.

**`dedupeKey` makes the send site retry-safe.** A double-submitted comment produces one
notification.

**`getRecipients` reads your own table**, once per send. easy-ping never owns your users.

**VAPID keys** are generated on first start and kept in the gitignored `.vapid-keys.json`.
